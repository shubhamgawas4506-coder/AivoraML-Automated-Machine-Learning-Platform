A clear request lifecycle

Each operation resolves the active project, validates its contract, executes locally, and returns either verified data or a structured error.

01

Send request

Use JSON for workflow actions or multipart form data for dataset uploads.

02

Validate scope

AivoraML checks request shape, project identity, and artifact ownership.

03

Execute workflow

The fitted pipeline and project state drive profiling, training, or prediction.

04

Receive contract

Responses use documented JSON schemas or verified downloadable files.

Project-aware operations

One active project.
Consistent artifact ownership.

The local workspace maintains an active project context. Routes that read generated notebooks, reports, models, or metrics accept a project identifier and reject access when that identifier does not own the artifact.

Project identifiers are validated before resolution Download routes verify existence and non-empty content Errors return safe codes without leaking server paths

Structured failure states

Errors you can act on

Non-success responses include an HTTP status and a concise detail. Artifact failures may also include a stable application error code.

400

Invalid request

The payload is syntactically valid but cannot be applied to the current workflow.

403

Project access denied

The requested project does not own the active artifact or workspace state.

404

Resource unavailable

The project, model, report, notebook, or requested file does not exist.

422

Contract mismatch

A field, query value, or request body failed schema validation.

500

Workflow failed safely

Generation or execution failed and returned a sanitized diagnostic code.
